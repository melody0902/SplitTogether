# 業務規則

## 權限

所有正式成員必須 Google 登入；Owner 建立群組時自動加入。非成員對群組及子資源一律 404，成員越權為 403。

| 行為 | Owner | Member |
|---|---|---|
| 查看群組所有帳務 | 可 | 可 |
| 新增支出、指定任一現有成員代墊 | 可 | 可 |
| 更正／軟刪除支出 | 全部 | 自己建立的 |
| 修改群組、產生／撤銷邀請、移除無歷史成員 | 可 | 不可 |
| 記錄還款 | 任意兩位不同成員 | 自己為付款方或收款方 |
| 作廢還款 | 全部 | 自己登記的 |

不移轉 Owner、不刪群組、不刪帳號。移除成員前檢查 LedgerMemberHistory，已刪除支出、作廢還款、曾參與後被更正移除的成員仍受保護。稽核操作人也保留關聯。

## 邀請

32 bytes 密碼學亂數轉為 64 位小寫 hex，資料庫存 SHA-256 hash；7 天有效、多次使用、可撤銷。登入後 POST 確認加入，重複加入為冪等。匿名只能看到群組名稱與期限，不能讀帳務。建立時 token 只回傳一次；後續邀請清單不再提供原始 token。

## 金額

TWD，單位「分」，資料库 bigint／C# long。單筆 1～100,000,000,000 分（十億元），自訂單人成員可分到零。輸入精度不得超過兩位小數。前端以 BigInt 從十進位字串解析，檢查範圍後轉成 safe integer 傳 API。彙總超過 ±9,007,199,254,740,991 分拒絕輸出。

Equal：按小寫 Guid 的 D 格式字串 ordinal 排序，再整數除法，每個餘分依序分配。前後端皆明確使用字串順序，不依賴資料庫預設排序。結果寫入 ExpenseSplits。

Custom：非負、成員唯一、總和恰等於支出。付款人不必參與分攤。表單與 API 都驗證。

## 餘額

淨餘額 = 已代墊 - 應負擔 + 已付還款 - 已收還款。
正數應收，負數應付；群組淨餘額和為零。還款不算消費。已刪支出／作廢還款不計入金額，但保留歷史。

結算依金額由大到小配對應付者與應收者，同額按 MemberId ordinal 決定順序；不保證全域最少交易次數。balances 回傳 Total、Members、Suggestions，由同一個群組鎖定期間取得。

## 修改、重送與還款

- 支出修改／刪除與群組修改帶 Version（Guid concurrency token），舊版本 409。
- 支出更正保留實際還款，重新計算可能產生反向應付款。UI 先確認。
- 還款只人工登記，可部分或超額；超額 UI 明確警告。不得當作付款已經銀行或對方確認。
- 還款不可編輯，可作廢後重登；重複作廢不重複扣款。
- 支出／還款建立以 GroupId + UserId + Operation + ClientRequestId 唯一。相同 key/內容回原 ID，相同 key 不同內容回 409。前端失敗重試保留 key。
- API hash 基於反序列化 DTO 的固定 JSON 序列化；不以時間／金額自動判斷重複。
- 支出、split、歴史關聯與冪等記錄同一個 SQL transaction 保存。
- 群組使用 PostgreSQL `pg_advisory_xact_lock`，以 SHA-256 衍生的固定 64-bit key 序列化所有成員變更、帳務寫入與快照查詢。鎖內重新檢查成員有效性，交易完成即釋放鎖。使用 READ COMMITTED，取得鎖後的查詢能看見上一個交易的提交。
